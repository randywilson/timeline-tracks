# Timeline Tracks — iOS

iOS port of the Android app at `../app/`. Same purpose: request GPS fixes at a user-set interval, keeping the device's location hardware active so that location-aware apps (Google Timeline, etc.) receive timely, accurate fixes. No data stored, no internet permission, GPL-3.0.

## Build

### Prerequisites

```bash
brew install xcodegen
```

### Regenerate Xcode project after editing project.yml

```bash
cd ios && xcodegen generate
```

Always regenerate after changing `project.yml`. The `.xcodeproj` is committed so Xcode can open without requiring xcodegen, but `project.yml` is the source of truth.

### Critical xcodegen gotchas

**`PRODUCT_NAME` must be set at the app target level only, never at project level.**
If set at the project level, the test target inherits it and gets Swift module name `TimelineTracks` instead of `TimelineTracksTests`, causing "Multiple commands produce TimelineTracks.swiftmodule" build errors.

**`Info.plist` must include all `CFBundle*` keys explicitly.**
When using `INFOPLIST_FILE` to point at a hand-written plist, Xcode does NOT auto-inject `CFBundleIdentifier`, `CFBundleExecutable`, `CFBundlePackageType`, etc. All of these must be present using build-setting variable references (`$(PRODUCT_BUNDLE_IDENTIFIER)`, `$(EXECUTABLE_NAME)`, etc.).

**Test target SDK must be set to simulator.**
Without `SDKROOT: iphonesimulator` and `SUPPORTED_PLATFORMS: iphonesimulator` in the test target settings, Xcode tries to build the test bundle for the device SDK and cannot find the simulator test host.

### Run on simulator

Open `TimelineTracks.xcodeproj` in Xcode, select an iPhone simulator, Cmd+R.

## Tests

### Run

Cmd+U in Xcode (or Product → Test). Tests run on the simulator — no device required.

### Test target setup

The test target uses `@testable import TimelineTracks` with `BUNDLE_LOADER`/`TEST_HOST` pointing at the app binary. Source files are NOT compiled directly into the test target. See `project.yml` for the exact settings.

### Test files

- `AutoStopCheckerTests.swift` — 10 cases: deque growth, 4-vs-5 trigger boundary, moving/stationary scenarios, distant fix breaks a run, recovery after distant fix scrolls out, reset
- `PrefsTests.swift` — 20 cases: all key defaults, round-trips, fallback behaviors (zero interval → 110, unknown raw string → default enum), raw value match to Android

### Auto-stop trigger count

The checker requires **5 total stationary points** (window of 4 + 1 new). The check that evicts a distant fix from the window still runs `allSatisfy` against it before removing it, so it takes 5 more stationary fixes after a distant fix enters the window before the trigger can fire.

## Platform API mapping

### Location

iOS has no equivalent to Android's interval-based GPS wakeup (`requestLocationUpdates(GPS_PROVIDER, intervalMs, ...)`). The app therefore offers two tracking modes:

**`continuous` mode ("Reliable" in UI)**

`startUpdatingLocation()` with `desiredAccuracy = kCLLocationAccuracyBest`. GPS chip runs at all times. In `locationManager(_:didUpdateLocations:)`, rate-limit by recording the last accepted fix time and ignoring newer ones until `intervalSecs` has elapsed.

**`periodic` mode ("Battery Saver" in UI)**

Run `CLLocationManager` at `desiredAccuracy = kCLLocationAccuracyThreeKilometers` (cell/WiFi — low drain). A `Timer` fires every `intervalSecs` and raises accuracy to `kCLLocationAccuracyBest`; when a fix arrives with `horizontalAccuracy <= 20` m, or after a 20-second timeout, drop back to `kCLLocationAccuracyThreeKilometers`.

Caveats for `periodic` mode:
- Whether the accuracy change triggers the GPS chip is undocumented — `locationd` may return a cached fix.
- Cold GPS acquisition takes 5–30 s; if no fix arrives within timeout, burst ends on whatever is available.
- Other apps only benefit if they have an active `CLLocationManager` at the moment the burst fires — iOS has no FLP cache equivalent.
- Battery is lower than `continuous` (~15–25% GPS duty cycle at 2 min interval) but not zero.

| Android | iOS `continuous` | iOS `periodic` |
|---|---|---|
| `GPS_PROVIDER` with interval | `kCLLocationAccuracyBest`, always-on | low-accuracy idle + timed burst |
| Chip sleeps between fixes | No | Approximately — not guaranteed |
| Reliable fix at each interval | Yes | Best-effort |

### How GPS sharing works on iOS

iOS does not share `CLLocationManager` fixes between apps. However, Core Location is shared hardware: when this app holds `kCLLocationAccuracyBest`, the GPS chip stays powered. Other apps (Google Timeline) receive timely fixes because the chip is already running. Same net effect as Android; mechanism is indirect.

### Background execution

- **`Info.plist`**: `UIBackgroundModes = [location]`
- **`CLLocationManager`**: `allowsBackgroundLocationUpdates = true`, `pausesLocationUpdatesAutomatically = false`

The OS shows a blue status-bar indicator while background location is active. No persistent notification needed — the indicator is sufficient. A local notification fires when tracking auto-stops.

### Permissions (two-step — not skippable)

1. `requestWhenInUseAuthorization()` → "Allow While Using App"
2. `requestAlwaysAuthorization()` → "Always Allow" (separate native dialog)

Both required for background operation. Also check `CLLocationManager.accuracyAuthorization`: if `.reducedAccuracy`, prompt user to enable precise location — auto-stop distance math requires real GPS coordinates.

### No battery optimization bypass

iOS has no `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` equivalent. `allowsBackgroundLocationUpdates = true` + `pausesLocationUpdatesAutomatically = false` is the maximum. OS may pause in Low Power Mode; document this in the app description.

## UI

Color palette (same as Android, defined in `Colors.swift`):
- Sky blue `#89B9D7` (`ttSkyBlue`) — title bar
- Ground brown `#B58251` (`ttBrown`) — main background
- Off-white `#FAFAFA` (`ttOffWhite`) — card background
- Near-black `#212121` (`ttNearBlack`) — primary text
- Green `#2E7D32` (`ttStartGreen`) — Start button

Layout mirrors Android:
- Interval field (numeric, default 110, max 6 digits)
- Auto-stop toggle (default on) + info button
- Mode picker: "Reliable" / "Battery Saver" + info button
- Start/Stop button (green/red)
- Stats (elapsed time, fix count, status) — hidden until running
- Permission warning banner (red, conditionally visible)
- "About · How it works" footer links

## App icon

The 1024×1024 icon at `Assets.xcassets/AppIcon.appiconset/AppIcon.png` was generated from the Android xxxhdpi launcher foreground PNG:

```bash
magick \
  -size 1024x1024 xc:"#89B9D7" \
  -fill "#B58251" -draw "rectangle 0,512 1023,1023" \
  \( app/src/main/res/drawable-xxxhdpi/ic_launcher_foreground.png -resize 1536x1536 \) \
  -gravity center -composite \
  -alpha off \
  ios/TimelineTracks/Assets.xcassets/AppIcon.appiconset/AppIcon.png
```

Run from the repo root. iOS clips to rounded corners automatically; the image must be square and have no alpha channel.

## Build and release

Minimum iOS target: **iOS 17.0** (set in `project.yml`).

```bash
# Build .ipa for distribution (requires Apple Developer account)
fastlane gym --scheme TimelineTracks --output_directory build/

# Upload to App Store Connect / TestFlight
fastlane deliver
```

**Apple Developer Program**: $99/year required to submit.

**Background location review scrutiny**: Apps with `UIBackgroundModes: [location]` get extra scrutiny. Reviewer note: "This app requests GPS fixes at a user-set interval to keep the device location hardware active, improving accuracy for Google Timeline and other navigation apps. It collects and stores no data." First submission may be rejected; one round of clarification is typical.

**Privacy Manifest** (`PrivacyInfo.xcprivacy`): Required since May 2024. Declares no data collected, no tracking, no third-party SDKs. Must be present or upload is auto-rejected.

**Signing**: Xcode automatic signing for development (`DEVELOPMENT_TEAM` in `project.yml`, currently blank). For CI/CD, use `fastlane match`.

**TestFlight path**: Archive → App Store Connect → internal testers immediately → external Beta Review (usually same-day) → App Store (24–72 hours first time).

## Workflow rules

- **Translations**: When English strings change, update all locale-specific `Localizable.strings` files under `ios/TimelineTracks/<locale>.lproj/` before committing. Locales to maintain: en, de, fr, es, pt-BR, ja, ko, zh-TW, hi, it, id (mirrors Android store locales).
- **Tests**: Run Cmd+U before committing changes to `AutoStopChecker.swift`, `Prefs.swift`, or `Models.swift`. Remind the user to do a background smoke test on a real device when `LocationTracker.swift` changes — simulator background mode is unreliable.
- **Background smoke test**: Start tracking, lock screen, wait 5+ minutes, unlock — confirm location count incremented. Core functional requirement; cannot be verified in Simulator.
- **project.yml changes**: Always run `cd ios && xcodegen generate` and verify the project builds before committing.
